# 工厂员工账号与订单权限方案

## 1. 方案目标

在现有工厂管理员和经销商账号之外，新增“工厂员工”角色，形成以下闭环：

1. 工厂管理员可新增、启用、停用和重置员工账号。
2. 管理员可将订单分配或转交给某一名员工。
3. 管理员可查看全工厂订单，以及按员工汇总的订单数量、状态、金额和跟进情况。
4. 员工登录后只能查看分配给自己的订单、分类统计、订单详情和本人跟进记录。
5. 员工不能通过搜索、导出、修改 URL 或直接请求接口读取同事订单。
6. 经销商账号的现有权限不因本功能发生变化。

## 2. 核心产品定义

### 2.1 什么是“员工自己的订单”

以订单的当前负责人为准：

```text
订单.assignedEmployeeUserId = 当前登录员工.userId
```

不能用订单创建人作为归属依据。订单可能由经销商、管理员或系统创建，再交由工厂员工处理。

### 2.2 第一期业务边界

- 一张订单只能有一名当前负责人。
- 新订单可以暂时未分配，只出现在管理员的“待分配订单”中。
- 管理员负责手动分配和转交订单。
- 员工可查看本人订单、填写跟进记录，并按业务需要更新有限的订单状态。
- 员工不能修改价格、删除订单、取消订单、分配订单或转交订单。
- 暂不做部门、组长、协作人、自动分单和绩效提成。

## 3. 角色与权限

| 功能 | 工厂管理员 | 工厂员工 | 经销商账号 |
| --- | --- | --- | --- |
| 新增、编辑、停用员工 | 允许 | 禁止 | 禁止 |
| 查看员工列表 | 允许 | 禁止 | 禁止 |
| 查看全工厂订单 | 允许 | 禁止 | 按现有经销商范围 |
| 查看本人订单 | 允许 | 允许 | 按现有经销商范围 |
| 查看按员工订单汇总 | 允许 | 仅本人汇总 | 禁止 |
| 分配、转交订单 | 允许 | 禁止 | 禁止 |
| 更新订单状态 | 允许 | 仅本人订单且限制状态 | 按现有规则 |
| 添加订单跟进 | 允许 | 仅本人订单 | 按现有规则 |
| 查看员工跟进汇总 | 允许 | 仅本人汇总 | 禁止 |
| 修改价格或报价 | 允许 | 禁止 | 按现有规则 |
| 导出订单 | 允许 | 第一期默认禁止 | 按现有规则 |
| 查看审计日志 | 允许 | 禁止 | 禁止 |

建议新增明确角色 `factory_employee`，不复用现有 `headquarters_sales`。现有销售角色可以管理客户、项目、设计、报价和订单，权限明显大于本需求。

## 4. 管理端功能

### 4.1 导航结构

新增一级分组“工厂团队”，包含：

- 员工账号
- 员工订单汇总

仅管理员可见。

### 4.2 员工账号页

顶部统计：

- 员工总数
- 启用账号数
- 停用账号数
- 未分配订单数

员工列表字段：

- 姓名
- 登录账号或邮箱
- 状态
- 当前负责订单数
- 待确认订单数
- 生产中订单数
- 待发货订单数
- 有效订单金额
- 今日待跟进数
- 逾期未跟进数
- 最近跟进时间
- 最近登录时间
- 创建时间

行操作：

- 查看订单
- 编辑姓名和联系方式
- 重置密码
- 停用或启用

员工不做物理删除。停用后保留历史订单和操作记录。

### 4.3 新增员工

表单字段：

- 姓名，必填
- 登录用户名，必填且全局唯一
- 邮箱，必填且全局唯一
- 初始密码，必填，不少于 12 位
- 联系电话，选填
- 备注，选填

提交后系统必须在一次业务操作中完成：

1. 创建登录用户和密码凭证。
2. 将用户加入当前工厂组织。
3. 赋予 `factory_employee` 角色。
4. 写入员工创建审计日志。

若邮箱已存在但尚未加入当前组织，可复用该用户并创建组织成员关系；若已经属于其他工厂，第一期禁止复用并提示管理员。

### 4.4 管理员订单页改造

订单列表新增：

- 负责人列
- 负责人筛选
- “未分配”筛选
- 分配负责人操作
- 转交负责人操作

分配或转交后记录：

- 订单 ID
- 原负责人
- 新负责人
- 操作管理员
- 操作时间

### 4.5 员工订单汇总页

默认按“当前负责人”汇总，每名员工展示：

- 全部订单数
- 待确认
- 已确认
- 待生产
- 生产中
- 待发货
- 已完成或已发货
- 已取消
- 有效订单金额
- 最近订单更新时间
- 跟进记录数
- 今日待跟进数
- 逾期未跟进数
- 长时间无跟进订单数

筛选条件：

- 时间范围
- 员工
- 订单状态
- 经销商
- 跟进状态

统计数字可以点击，下钻到使用相同筛选口径的订单明细。

金额口径：排除已取消订单，按订单当前有效金额汇总。第一期这是运营汇总，不定义为绩效或提成数据。

## 5. 员工端功能

### 5.1 首页

员工登录后只展示：

- 我的全部订单
- 我的待确认订单
- 我的生产中订单
- 我的待发货订单
- 我的今日待跟进
- 我的逾期未跟进
- 我的最近订单

### 5.2 我的订单

复用现有订单状态分类：全部、待确认、已确认、待生产、生产中、待发货、已发货。

员工看到的列表数据必须已经由后端按当前用户过滤。前端不传入可任意修改的员工 ID 来决定数据范围。

### 5.3 订单详情

员工只能打开本人负责的订单。访问同事订单 ID 时，服务端统一返回 `404`，避免泄露该订单是否存在。

第一期允许的操作建议为：

- 查看订单基础信息、配置快照和生产信息。
- 查看并新增本人订单的跟进记录。
- 设置下次跟进时间。
- 按预设状态机更新本人订单的处理状态。

第一期禁止的操作建议为：

- 修改订单价格和报价快照。
- 删除或取消订单。
- 创建发运单。
- 修改订单负责人。
- 查看审计日志和其他账号信息。

## 6. 数据设计

现有 `user`、`account`、`member` 和 `organization` 可以继续作为员工账号基础模型，不需要另建一套登录系统。

### 6.1 角色

在公共角色枚举、Better Auth 组织角色、API 角色标准化和 ERP 前端角色中加入：

```text
factory_employee
```

### 6.2 订单字段

在 `orders` 增加：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `assigned_employee_user_id` | text, nullable | 当前负责人，关联 user.id |
| `assigned_at` | timestamptz, nullable | 最近一次分配时间 |
| `assigned_by_user_id` | text, nullable | 最近一次执行分配的管理员 |

增加索引：

```text
(tenant_id, assigned_employee_user_id)
(tenant_id, status, assigned_employee_user_id)
```

旧订单迁移时将负责人设为 `null`，统一进入“未分配订单”，不根据创建人自动猜测归属。

### 6.3 分配历史

建议新增 `order_assignments` 表，而不是只依赖通用审计日志：

| 字段 | 说明 |
| --- | --- |
| `id` | 记录 ID |
| `tenant_id` | 工厂组织 |
| `order_id` | 订单 |
| `from_user_id` | 原负责人，可为空 |
| `to_user_id` | 新负责人，可为空 |
| `assigned_by_user_id` | 操作管理员 |
| `created_at` | 操作时间 |

### 6.4 订单跟进记录

新增 `order_follow_ups` 表：

| 字段 | 说明 |
| --- | --- |
| `id` | 跟进记录 ID |
| `tenant_id` | 工厂组织 |
| `order_id` | 订单 |
| `employee_user_id` | 实际跟进员工 |
| `content` | 跟进内容 |
| `next_follow_up_at` | 下次跟进时间，可为空 |
| `created_at` | 跟进时间 |

历史跟进记录永远归属实际填写人。订单转交后，旧记录不会改到新负责人名下；当前订单数量和金额则归属订单当前负责人。

## 7. 后端权限实现

员工权限必须由“角色权限 + 数据范围”共同控制。

### 7.1 统一订单访问范围

Repository 层引入统一范围对象：

```ts
interface OrderAccessScope {
  tenantId: string;
  assignedEmployeeUserId?: string;
}
```

- 管理员：只有 `tenantId`，可读取当前工厂全部订单。
- 工厂员工：同时带 `tenantId` 和当前 `userId`。
- 经销商：继续使用现有经销商组织隔离规则，后续不可与员工范围混用。

列表、详情、状态修改、附件和导出必须复用同一个访问范围，不能只在订单列表接口过滤。

### 7.2 账号接口

建议新增或调整：

| 方法 | 接口 | 权限 | 用途 |
| --- | --- | --- | --- |
| `GET` | `/api/employees` | 管理员 | 员工列表 |
| `POST` | `/api/employees` | 管理员 | 创建员工账号和组织成员 |
| `PATCH` | `/api/employees/:id` | 管理员 | 编辑员工资料 |
| `PATCH` | `/api/employees/:id/status` | 管理员 | 启用或停用 |
| `POST` | `/api/employees/:id/reset-password` | 管理员 | 重置密码 |
| `GET` | `/api/employees/order-summary` | 管理员 | 全员订单聚合 |
| `GET` | `/api/employees/follow-up-summary` | 管理员 | 全员跟进聚合 |
| `PATCH` | `/api/orders/:id/assignee` | 管理员 | 分配或转交订单 |
| `GET` | `/api/orders` | 登录用户 | 服务端按角色自动限定数据范围 |
| `GET` | `/api/orders/:id` | 登录用户 | 服务端按角色校验详情范围 |
| `GET` | `/api/orders/:id/follow-ups` | 管理员或负责人 | 查看有权订单的跟进记录 |
| `POST` | `/api/orders/:id/follow-ups` | 管理员或负责人 | 新增跟进记录 |

不建议让员工端通过 `/api/orders?employeeId=xxx` 决定查询谁的订单。员工身份下必须忽略或拒绝该参数，并强制使用当前会话用户 ID。

### 7.3 现有接口需要同步收紧

当前账号列表接口只要求登录，没有管理员角色限制。员工角色上线前，必须把账号列表、经销商列表、价格表和审计等敏感读取接口按角色收紧，避免员工获得不必要的数据。

## 8. 前端改造

### 8.1 管理员端

- 新增“工厂团队”导航和员工账号页。
- 新增员工订单汇总页。
- 在员工详情和汇总页展示跟进数量、今日待跟进和逾期未跟进。
- 订单列表增加负责人列、筛选和分配操作。
- 订单详情显示当前负责人和分配历史。

### 8.2 员工端

- 增加 `factory_employee` 前端角色和角色名称。
- 只开放仪表盘、我的订单、本人订单详情。
- 增加我的跟进记录、今日待跟进和逾期未跟进。

## 10. 分期建议

### P0：账号和订单隔离

- 员工账号新增、启停、重置密码。
- 员工角色和服务端订单行级隔离。
- 订单负责人字段。
- 管理员分配和转交订单。
- 管理员按员工查看订单数量、金额和状态汇总。
- 基础订单跟进记录、下次跟进时间和按员工跟进汇总。
- 员工查看自己的订单分类和详情。
- 员工查看自己的待跟进分类并填写跟进记录。
- 分配和账号操作审计。

### P1：跟进增强

- 自动提醒和站内通知。
- 跟进模板和跟进结果标签。
- 长时间未跟进规则配置。
- 批量分配和批量转交。
- 按权限导出订单。

### P2：组织与绩效

- 部门和员工分组。
- 组长查看本组订单。
- 自动分单规则。
- 员工目标、完成率和响应时长。
- 成交贡献人与绩效口径。

## 11. 验收标准

1. 管理员可以创建员工，员工可使用独立账号登录。
2. 员工 A 的订单列表和分类统计只包含分配给 A 的订单。
3. 员工 A 搜索员工 B 的订单号时得不到结果。
4. 员工 A 直接访问员工 B 的订单 URL 或 API 时返回 404。
5. 管理员可以查看全工厂订单和按员工汇总，并下钻到对应明细。
6. 订单转交后，原员工立即失去访问权限，新员工立即获得权限。
7. 停用员工后不能再进入工厂工作区，历史订单和操作记录仍保留。
8. 未分配订单只对管理员可见。
9. 汇总数量和金额与相同筛选条件下的订单明细完全一致。
10. 经销商账号原有权限和数据范围不受影响。
11. 员工无法读取账号列表、价格表、审计日志等未授权数据。
12. 创建员工、停用员工、分配和转交订单均有审计记录。
13. 员工只能查看和填写本人订单的跟进，管理员可查看每名员工的跟进汇总。
14. 今日待跟进、逾期未跟进的汇总数字与下钻明细一致。

## 12. 上线前默认决策

为了让第一期可以直接执行，采用以下默认值：

- 订单由管理员手动分配。
- 一张订单只有一名当前负责人。
- 员工默认不能导出订单。
- 员工不能改价格、取消订单、创建发运单或转交订单。
- 员工可更新哪些订单状态，在开发前按现有状态机单独列白名单。
- 离职员工只停用不删除，未完成订单必须先批量转交或回到未分配池。
